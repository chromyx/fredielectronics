# Fredi Electronics website – shared project context

This file is the single source of project context. Work happens on two PCs, a phone and Claude Code Cloud, so **everything Claude needs to know lives here and in `ROADMAP.md`, never in local memory.**

## Session routine (every session, any device)

**Start:** `git pull`, read this file and `ROADMAP.md`, then tell the user in 3 lines where we left off.

**End (before stopping):** update "Current state" and add a "Session log" entry (today's date, what was done) below, update `ROADMAP.md`, commit everything with a clear message, and push to `main`.

A hook in `.claude/settings.json` (`.claude/hooks/session-reminder.mjs`) reminds Claude of this on the first message of each session and whenever the user types after a 30+ minute break. It needs `node` on PATH (Windows uses Git Bash for hooks).

## What the project is

Rebuild of fredielectronics.com as a bilingual portfolio site for investors and clients: Albanian at `/` (default), English at `/en`. The client is Fredi Electronics sh.p.k., Tirana (LED screens, audio, conference, security & access, energy & UPS, electrical/electronic accessories). Ecler is their exclusive audio partner.

**Stack:** Next.js 16 (App Router, Turbopack) + React 19, Payload CMS 3 (admin at `/admin`, also the REST/GraphQL API), SQLite via `@payloadcms/db-sqlite`, Lexical rich text, `sharp` for images, GSAP + Lenis for homepage motion. TypeScript throughout. Node `^22.23.4 || >=24.22.1` (CI and Docker use Node 24). Deployed to Namecheap shared hosting by GitHub Actions; Docker for always-on local runs.

> Next.js 16 has breaking changes from older versions. `site/AGENTS.md` (written by `next dev`) says to check `site/node_modules/next/dist/docs/` before writing Next code.

## Install, run, build, test

All commands run in `site/`. The repo is public: never commit `.env`, `data/`, `ADMIN-LOGIN.txt` or passwords.

**Clone** (some photo paths are longer than Windows allows by default):

```
git clone -c core.longpaths=true https://github.com/chromyx/fredielectronics.git
```

If a clone was made without it: `git config core.longpaths true`, then `git restore --source=HEAD :/` and `git reset`.

**First-time setup**

| Step | Windows (PowerShell) | Linux / Cloud (bash) |
|---|---|---|
| Install | `npm ci` | `npm ci` |
| Env file | `Copy-Item .env.example .env` | `cp .env.example .env` |
| Secret | `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` → paste into `PAYLOAD_SECRET` in `.env` | `sed -i "s/^PAYLOAD_SECRET=.*/PAYLOAD_SECRET=$(openssl rand -hex 32)/" .env` |
| Database | `New-Item -ItemType Directory -Force data; Copy-Item content-db/fredi.db data/fredi.db` | `mkdir -p data && cp content-db/fredi.db data/fredi.db` |

`content-db/fredi.db` holds all content (75 projects, services, brands, texts, settings) without logins or messages. With no users, `/admin` asks you to create the first admin.

**Run, build, check** (same on both OSes)

- Dev server: `npm run dev` → http://localhost:3000, `/en`, `/admin`
- Production build: `npm run build`, then `npm start`
- Always-on in Docker: `docker compose up -d --build` (container `fredi-site`, port 3000, mounts `data/` and `media/`); stop with `docker compose down`. Don't run it alongside `npm run dev`; both use port 3000.
- Type check: `npx tsc --noEmit` (passes)
- Lint: `npx eslint .` (**currently broken**, see Current state)
- Tests: there are none. Check changes by running the dev server and loading `/`, `/en`, `/sherbimet/led`, `/projektet/led`, `/admin`.
- Regenerate Payload types after changing collections/globals: `npm run generate:types`
- One-off content scripts: `npx payload run src/seed/<file>.ts`

**Deploy:** pushing to `main` with changes under `site/` runs `.github/workflows/deploy-namecheap.yml`. It builds a standalone app and uploads it to the `namecheap-build` GitHub release; the server's cron (`site/deploy/namecheap/update.sh`, every 5 min) installs it. Content edits made in the live admin stay on the server and are not in git.

## Folder structure

- `site/` – the real site (Next.js + Payload). `site/README.md` is the plain-language guide to running it and using the admin.
  - `src/app/(frontend)/` – public pages: home, `sherbimet/[slug]`, `projektet/[cat]`, `en/…`, `[...missing]` (branded 404)
  - `src/app/(payload)/` – admin and API routes (generated by Payload)
  - `src/collections/`, `src/globals/` – CMS schema; `src/payload.config.ts` wires them
  - `src/components/` – page components (`Site`, `ServicePage`, `CategoryPage`, `HeroWall`, `Viewer`, …)
  - `src/lib/` – data loaders (`getHomeData.ts`), `cats.ts`, `routes.ts`, `seo.ts`, `ui.ts`
  - `src/seed/` – import and one-off content scripts
  - `src/redirects.ts` – old WordPress URLs → new; `src/proxy.ts` – passes the path to pages for the 404 language
  - `content-db/` – clean content database for new setups; `media/` – uploaded photos; `deploy/namecheap/` – server update script
- `fotot-finale/` – finished-product photos per project, sorted by category (rebuilt by `src/seed/export-sorted.ts`)
- `Te-gjitha-fotot/` – all photos, de-duplicated, compared with the old WordPress site; `6 - E panjohur` = unknown photos
- `backup/` – scrape of the old WordPress site (one 386 MB video is only on the original PC)
- `drive/` – assets from the client's Google Drive (logos, FAV/TEG, project folders)
- `design-preview/`, `tools/` – early static mockups and helper scripts
- `.github/workflows/` – Namecheap deploy; `.claude/` – shared Claude Code settings, hook, launch config

## Working rules and conventions

**Code**
- Browser components import `CATS` from `src/lib/cats.ts`, never values from `getHomeData.ts`, which would pull Payload into the client bundle.
- Data loading happens in server components via `src/lib/getHomeData.ts`.
- Content changes are scripts in `src/seed/`, run with `npx payload run …`. In production (Docker/Namecheap) the schema is not pushed automatically: after adding fields, run a payload script once locally first, and regenerate `src/payload-types.ts`.
- Routes: `/sherbimet/<led|audio|conference|security|power|accessories>`, `/projektet/<led|audio|conference|security|power>`; English at `/en/services/…` and `/en/projects/…`. Keep `src/redirects.ts` for old WordPress URLs.
- Collections: Projects (category led/av/conf/sec/power, gallery, heroPhoto, featured = homepage slideshow, order), Services, Brands, Media, Clients, Messages, Users. Globals: HomePage, SiteSettings (contact, hours, socials).
- Motion: GSAP + Lenis on the homepage only; inner pages use CSS animation gated by `html.motion.ready`. Always respect reduced motion.
- Comments and commit messages are plain English that explain *why*. Commits are small and descriptive.

**Client decisions (keep to these)**
- Design: clean, calm, investor-grade, SOE-style (soe.org.uk), navy `#141c2a`. No gimmicks: no pixel effects, cursor lenses, hover previews or scroll-jacking.
- Photos: finished products only. No people, tools, ladders, boxes, half-built screens or social-media graphics.
- Homepage shows partner brands, not institutions; institutions appear only inside projects. No project counts anywhere (menus, tabs, filters, buttons).
- FAV × TEG section (fav.al, LED ad network in TEG mall) uses the FAV palette: blue `#042c8c`, deep `#00165b`, magenta `#e50095`.
- Fredi does not sell laptops. Ecler is its own section on the Audio page.
- Hours: Mon–Fri 08:00–17:00, Sat 08:00–14:00, Sun closed. Contact: +355 69 675 2032 (also WhatsApp), fredielectronics@gmail.com and info@fredielectronics.com, Rr. Kavajës P.207, Tiranë.
- Socials: Instagram @fredielectronics, facebook.com/fredielectronics, linkedin.com/in/fredielectronics (chosen by the client 2026-11-18; a company page also exists at linkedin.com/company/fredi-electronics-shpk).
- Service page hero = "LED wall": the photo is split into cabinets and changes project in a diagonal wave.
- Homepage slideshow: Bashkia Korçë, Durrës, Shkolla e Magjistraturës, Zoe Hora, Plaza and others; set via `src/seed/hero-slides.ts`. Leave the Magjistratura room as it is.
- The Tirana Fair 2025 stand and Match Maker 2026 stand are the same stand, merged into one project.
- Products/shop will come later in the same admin.

**Secrets:** the original PC holds the live `site/data/fredi.db` and `site/ADMIN-LOGIN.txt`; neither goes in git. Server secrets live only on Namecheap.
